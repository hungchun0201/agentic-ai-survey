ZipServ: Fast and Memory-Efficient LLM Inference with Hardware-Aware Lossless Compression

A fused compression-GEMM path that changes the memory traffic assumptions behind dense LLM inference.

Ruibo Fan, Xiangrui Yu, Xinglin Pan, Zeyu Li, Weile Luo, Qiang Wang, Wei Wang, Xiaowen Chu · HKUST(GZ) / HIT Shenzhen / HKUST

arXiv:2603.17435Lossless compressionZipGEMML40S/4090/5090Open source

1. Problem

Lossless model compression is attractive because it preserves bit-exact weights while reducing memory footprint and bandwidth demand. Conventional entropy codecs, however, are a poor match for GPU inference: variable-length bitstreams break SIMD/SIMT regularity and decoupled decompression adds memory traffic.

Figure 1 from the paper: existing lossless-compression pipelines often slow inference despite saving memory.
System overview from the paper: ZipServ integrates encoding format, ZipGEMM, and serving runtime.

2. Method

ZipServ introduces Tensor-Core-Aware Triple Bitmap Encoding, a fixed-length representation tailored to BF16 exponent structure. ZipGEMM then loads compressed weights and reconstructs them directly into Tensor Core registers, avoiding an intermediate decompressed buffer.

TCA-TBEFixed-length bitmap encoding keeps decoding parallel and regular.
ZipGEMMFuses decompression with GEMM in the Tensor Core path.
Stage-aware runtimeUses fused execution where memory-bound decode benefits and avoids harming compute-bound prefill.

The evaluation includes RTX4090, L40S, RTX5090, A100, and H800 experiments, with LLaMA3.1, Qwen2.5, Gemma3, and Mistral model families. This is valuable for the current repo because L40S and non-Hopper parts appear in the target hardware set.

4. Relation to This Repo

  • The current roofline predictor should mark weight-compressed GEMM as out of scope unless memory traffic and compute-intensity constants are changed.
  • ZipServ supports the repo premise that decode and memory traffic remain central, but it changes the operator implementation rather than just scheduling it.
  • It is useful related work for any section discussing hardware-aware deviations from vanilla BF16/FP16 GEMM assumptions.

5. Limitations

ZipServ targets lossless weight compression. It does not compress KV cache, model request scheduling, or framework overhead; it should be treated as a kernel/operator path that changes the roofline inputs.
