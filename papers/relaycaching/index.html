RelayCaching

Accelerating LLM Collaboration via Decoding KV Cache Reuse — treating one agent's decode-phase KV cache as a high-fidelity draft for the next agent's prefill, corrected by sparse per-token rectification.

arXiv:2603.13289 Preprint, Feb 2026 Multi-Agent LLM KV Cache Reuse Training-free Decode→Prefill

Yingsheng Geng, Yuchong Gao, Weihong Wu, Guyue Liu, Jiang Liu

arXiv:2603.13289v1 [cs.LG], submitted 28 February 2026

1. The Problem: Every Agent Re-Prefills the Last Agent's Output

A multi-agent LLM system decomposes a task across specialized agents that communicate by writing text to one another. The content one agent decodes becomes verbatim input that the next agent must read. Because reading in a transformer means running a prefill pass to build the key-value (KV) cache, every hand-off re-encodes text that was already turned into KV state one stage earlier. This section builds the case that the redundant re-prefill is the dominant, growing latency term in collaborative inference, and that the obvious ways to remove it either break accuracy or fail on the positions where agent text actually lands.

1.1 Why now — collaboration replaced the monolith

The dominant deployment pattern for hard tasks shifted from a single large model answering in one shot to orchestrated multi-agent programs — planner, coder, reviewer, tool-caller — that pass structured messages through many rounds. In these programs the shared context is monotonically accumulating: an Architect emits a specification, a Developer reads that specification and emits code, and a Reviewer reads specification plus code and emits a critique. Each downstream agent's prompt is the concatenation of everything its predecessors produced, so the prefill length of the last agent in a five-stage program can be an order of magnitude larger than the first. Pre-2024 serving stacks were tuned for one- to three-turn chat, where the prompt is short and mostly static; the 2026 collaborative workload instead spends the majority of its wall-clock time re-reading dynamically generated text that no static cache anticipated.

Bottom: (a) prefix caching fails because the shared content is not a prefix; (b) pre-computed caching cannot handle dynamically generated content; (c) RelayCaching enables decode-to-prefill reuse via selective rectification.

1.2 A concrete trace — the Reviewer waits 3.89 seconds before it can think

Consider the three-stage program of Figure 1 running on a small model. The Architect decodes an 800-token specification. The Developer must first prefill that 800-token specification before it can begin decoding its 2,048-token code body; the Reviewer must then prefill the specification and the code — roughly 2,900 tokens — before it can emit its first critique token. In the paper's scaling measurement the cumulative reused context grows from 512 to 12,288 tokens as agents are chained, and a standard full-prefill pipeline spends 3.89 seconds building the KV cache of the final agent before that agent produces a single output token. That 3.89 seconds is pure re-encoding of text the pipeline already saw; from the user's standpoint it is dead time between the moment the previous agent finished writing and the moment the next agent starts responding.

1.3 The status-quo cost, quantified

The redundant prefill is not a rounding error. On the paper's per-agent breakdown (Qwen3-0.6B, 512-token prefix, 2,048-token output), time-to-first-token grows from 85.2 ms with two agents to 493.9 ms with five, and essentially all of that increase is re-encoding of shared upstream text. On the long-context measurement the same term reaches 3.89 seconds at 12,288 cumulative tokens. Beyond latency, the redundant KV state also inflates memory: the final agent materializes a cache for the entire accumulated transcript even though most of that transcript was already resident one stage earlier. Any serving stack that treats each agent as an independent request pays this cost on every hand-off in every program.

1.4 Why the obvious fixes fail

The reader immediately asks why the shared text is not simply cached and reused. Two established families of KV reuse exist, and the multi-agent setting breaks both. Prefix caching, as implemented in vLLM and SGLang, reuses a cached KV block only when the new request begins with exactly the same tokens at exactly the same positions. In a collaborative program the shared content almost never sits at the prefix — the Reviewer's prompt places the specification after its own system instructions and after the code, at non-prefix positions — so the strict positional-alignment requirement is violated and the cache is discarded. Pre-computed caching, exemplified by CacheBlend and EPIC, relaxes the prefix constraint by encoding reusable chunks offline and stitching them in at arbitrary positions, but it assumes the reusable content is static and known in advance, such as retrieval documents in a RAG pipeline. Agent outputs are generated at run time and are never available for offline encoding, so pre-computed caching has nothing to load.

1.5 The fundamental obstacle — the reused cache is close but not identical

There is one cache the collaborative setting does possess for free: the KV state the upstream agent built while decoding its own output. That decoding KV cache already encodes exactly the tokens the downstream agent needs to read. The obstacle is that decoding KV and prefill KV for the same tokens are not bit-identical. When the upstream agent decoded the text it attended to one context; when the downstream agent prefills the same text it sits under a different prefix, and that prefix perturbs the attention that produces the key and value vectors. Reusing the decoding cache verbatim therefore injects a small error, and reusing it blindly across an entire agent chain lets that error compound. The naive correction — recompute the whole thing under the new prefix — is exactly the full prefill the method is trying to avoid. The real problem is therefore not whether the decoding cache is reusable, but whether the small set of positions where it genuinely deviates can be located and repaired without paying for the full prefill that would reveal them. RelayCaching's contribution is an empirical characterization showing that this deviating set is sparse and structured, plus a mechanism that finds and rectifies it cheaply.

1.6 Position versus immediate prior work

RelayCaching sits among a small set of cross-context KV reuse methods, and it is defined largely by what each of them leaves unaddressed for the dynamic multi-agent case.

RelayCaching's stance is that no external reference is necessary — the upstream decoding cache is itself the best available approximation of the downstream prefill cache, and the only remaining work is to find and fix the sparse positions where the approximation is wrong.

2. RelayCaching at a Glance

Having established that the upstream decoding cache is a close-but-imperfect draft of the downstream prefill cache, this section previews the paper's answer before the detailed mechanism. RelayCaching is a training-free inference method that reuses the decoding KV cache directly and repairs it in place, confining the repair to a narrow band of layers and a sparse set of tokens so that the reuse rate stays above 80% while accuracy tracks full prefilling.

The design rests on three empirical regularities (Section 3): the decoding cache is globally very close to the prefill cache, its deviation is concentrated in the middle layers in a U-shaped profile, and within those layers only a sparse and inter-layer-correlated set of tokens deviates. Because the deviation is confined this way, the method never has to recompute a full layer or a full sequence — it recomputes a handful of tokens in a middle band and reuses the rest verbatim.

3. Observations: Why the Draft Is Almost Right

The method is only justified if the decoding cache really is a good draft and its errors really are localized. Section 3 of the paper is an empirical characterization that answers exactly this, comparing decoding KV caches against their full-prefill counterparts and reporting three findings that together license direct reuse with targeted rectification. This section walks each finding and the measurement behind it.

3.1 High macro-level alignment — value cosine is the weak axis

The first finding is that, despite the prefix difference, decoding and full-prefill KV caches for the same tokens are on average very close. The paper measures both cosine similarity and norm similarity between the two caches across all layers and tokens on 2WikiMQA, and contrasts them against two lower bounds: a Random KV baseline and an Independent KV baseline in which the content is encoded without the shared context. The decoding cache sits far above both baselines, confirming that it carries genuine information about the tokens rather than noise. Among the metrics, value cosine similarity is the lowest — the axis along which the caches disagree most — so the rest of the analysis focuses on value cosine deviation as the quantity to detect and repair.

Figure 2 (from paper): Average cosine and norm similarity between decoding KV caches and full-prefill KV caches across layers and tokens on 2WikiMQA, compared against Random KV and Independent KV. The decoding cache is far closer to the full-prefill reference than either baseline; value cosine similarity is the lowest metric and becomes the focus of subsequent analysis.

Formally, the token-wise value deviation at layer $\ell$ for position $j$ is one minus the head-averaged cosine similarity between the reused value vector and the full-prefill value vector:

(1) $$d_{j,\ell} = 1 - \frac{1}{H}\sum_{h=1}^{H} \cos\!\left(v^{\text{reuse}}_{h,j,\ell},\; v^{\text{full}}_{h,j,\ell}\right)$$

Aggregating this deviation over the reused positions gives a layer-wise similarity score that summarizes how faithful the reused cache is at each depth:

(2) $$s_\ell = \frac{1}{\left|\mathcal{I}_{\text{reuse}}\right|}\sum_{j\in\mathcal{I}_{\text{reuse}}}\left(1 - d_{j,\ell}\right)$$

3.2 U-shaped layer-wise deviation — the error lives in the middle

The second finding refines where the disagreement sits. Plotting $s_\ell$ against layer index reveals a distinct U shape in value cosine similarity: shallow layers and deep layers remain highly faithful, while the middle layers dip — they carry the largest deviation and, when left uncorrected, dominate the degradation of downstream generation quality. The right panel confirms causality by a recovery experiment: replacing the reused decoding KV with true full-prefill KV up to or from a given layer shows that repairing the middle band recovers almost all of the lost fidelity, whereas repairing the already-faithful shallow or deep layers buys little. This is what lets the profiler bound recomputation to a middle layer range $[L_{\text{start}}, L_{\text{end}}]$ and skip the rest entirely.

Figure 3a: Layer-wise similarity between decoding and full-prefill KV caches. The value cosine similarity (red) traces a U shape: high at shallow and deep layers, lowest in the middle.
Figure 3b: Relative recovery of value cosine similarity for post-reuse tokens when decoding KV is replaced by full-prefill KV up to, or from, a given layer index. Recomputing the middle layers yields the most efficient recovery.

3.3 Sparse, correlated token-wise deviation — few tokens, and they persist

The third finding localizes the error within the middle layers to a small set of token positions. Averaged over the middle layers, the token-wise deviation profile is sparse: most positions retain high fidelity, and only a minority spike. Two structural properties make these spikes exploitable. First, the high-deviation positions are consistent across the middle layers rather than scattering randomly per layer, so they can be identified at a single detection layer instead of every layer. Second, a Spearman rank-correlation analysis of value cosine deviation between adjacent layers is high, meaning that once a position emerges as high-deviation it tends to stay high-deviation deeper in the stack — the pattern is persistent and therefore predictable. Together these justify selecting tokens once, at one detection layer, and rectifying that same set across the whole middle band.

Figure 4a: Token-wise similarity between decoding and full-prefill KV caches, averaged over layers. The profile is sparse — most tokens retain high fidelity, and a small set spikes in deviation.
Figure 4b: Spearman rank correlation of token-wise value cosine deviations between adjacent layers. The high correlation shows that high-deviation positions, once they emerge, persist across depth — the deviation is predictable.
Reading these three findings together: the decoding cache is globally faithful, its residual error is confined to a middle layer band, and inside that band the error is carried by a sparse, persistent set of tokens. Each finding removes one dimension of work: macro alignment removes the need to recompute at all in the common case, the U shape removes the shallow and deep layers, and token sparsity removes all but a few positions. What remains is a small rectangle in the (layer, token) grid — and that is the only region RelayCaching ever recomputes.

4. Architecture: Profile Offline, Capture at Decode, Rectify at Prefill

RelayCaching turns the three observations into a pipeline with one offline stage and two online stages. Offline, a layer-range profiler reads the U-shaped profile from calibration data. Online, while the upstream agent decodes, a cache manager stores the reusable KV and accumulates the influence signal; then, when the downstream agent prefills, the method re-aligns the cache to the new positions, selects the tokens to fix, and rectifies only those. This section describes the data flow; Sections 5 and 6 detail the profiler and the selector.

Figure 5 (from paper): (1) An offline layer-range profiler identifies a critical layer range and a detection layer from calibration data. (2) During stage-(i−1) decoding, the cache manager stores pre-RoPE KV caches, saves hidden states at L_start, and accumulates influence scores. (3) At stage-i prefilling, RelayCaching re-applies RoPE to align reused KV to the new positions, performs token selection at the detection layer via combined deviation- and influence-based criteria, and applies sparse rectification on the selected tokens within the layer range.

A subtle but essential detail is positional alignment. The upstream agent decoded its tokens at one set of absolute positions, but the downstream agent reads the same tokens at different positions in its own prompt. RelayCaching therefore stores the KV cache before rotary position embedding (pre-RoPE) is applied, and at reuse time re-applies RoPE for the new positions. This is precisely what lets the method work where prefix caching cannot: the reused content can land at any non-prefix position, because the rotary phase is re-derived from the downstream position rather than baked in at decode time.

4.1 The decode-time bookkeeping and why it is nearly free

The two online stages divide the work so that the expensive step never runs on the critical path. Everything the downstream rectification will need is captured while the upstream agent is already decoding — a phase that is memory-bandwidth-bound and has spare compute — so the extra bookkeeping overlaps with work that was happening anyway. Three things are recorded, and each maps directly to something the prefill stage would otherwise have to recompute.

Stored at decode Why it is needed at prefill
Pre-RoPE KV cache Storing the cache before rotary embedding lets the reuse stage re-apply RoPE at whatever downstream position the content lands, which is what breaks the prefix-only restriction of ordinary caching.
Hidden states at $L_{\text{start}}$ Rectifying a token inside the middle band requires its layer-$L_{\text{start}}$ input. Checkpointing that one layer's hidden state means the shallow layers never have to be re-run for the recomputed tokens.
Accumulated influence $s_{\text{inf}}(j)$ The influence criterion (Eq. 6) sums attention across decode steps. It can only be collected as decoding happens, so it is accumulated online rather than reconstructed later.

The checkpoint at $L_{\text{start}}$ is the detail that makes rectification cheap rather than merely selective. Without it, recomputing a middle-band token would still require running every shallow layer up to $L_{\text{start}}$ for that token; with it, the recomputation starts from the saved hidden state and touches only the layers inside the band. The reuse rate reported by the paper is therefore a faithful proxy for the compute saved: a token outside the selected set costs nothing at prefill, and a token inside it costs only the middle-band layers rather than the full stack.

5. The Layer-Range Profiler

The profiler converts the U-shaped similarity curve into two concrete outputs used at run time: the boundaries of the middle band to recompute, and the single layer at which token selection is performed. Both are read from a small calibration set once per model, so the profiler adds no per-request cost. This section states the two rules the paper uses.

5.1 Bounding the critical layer range

The end of the deviation-prone band is detected as the depth at which the similarity has both recovered above a data-derived threshold and stopped changing appreciably between adjacent layers. Writing $\mu_{\text{last}}$ and $\sigma_{\text{last}}$ for the mean and standard deviation of similarity in the deep, stable layers, the end layer is the first depth $\ell$ satisfying

(3) $$s_\ell \geq b \quad\wedge\quad \left|s_\ell - s_{\ell-1}\right| < \lambda\,\sigma_{\text{last}}, \qquad b = \mu_{\text{last}} - \sigma_{\text{last}}$$

The first clause requires the similarity to have climbed back into the stable regime; the second requires the curve to have flattened, so the chosen boundary is where the U has genuinely ended rather than a local wobble. The start of the band is set symmetrically at the shallow side where the similarity first departs from the stable regime, giving the range $[L_{\text{start}}, L_{\text{end}}]$.

5.2 Picking the detection layer

Token selection needs one representative layer at which the deviating positions are already clearly separated from the faithful ones. The paper finds this transition point from the inter-layer deviation-correlation profile by locating where its curvature flips sign. Letting $\rho_\ell$ denote the correlation-profile value at layer $\ell$, the second-order difference

(4) $$\alpha_\ell = \rho_\ell - 2\,\rho_{\ell-1} + \rho_{\ell-2}$$

marks the layer where the correlation profile transitions from rising to falling — the point at which the persistent high-deviation set has fully emerged. That layer is chosen as the detection layer $L_{\text{det}}$, and all per-token scoring is read there. Because Section 3.3 established that the high-deviation set persists across depth, a set chosen at $L_{\text{det}}$ is a reliable proxy for the set that needs fixing across the whole band.

6. Token Selection: Two Criteria, One Union

This is the mechanism most relevant to our own line of work, so it is worth stating with care. At the detection layer, RelayCaching decides which reused tokens to recompute by scoring every position under two independent criteria and taking their union. The first criterion asks which tokens are most unfaithful to the full-prefill reference; the second asks which tokens matter most to the generation, as measured by the attention they received. Both are per-token, and both feed the same additive action — recompute the selected token's KV inside the middle band.

6.1 Deviation-based selection — repair what is most wrong

The deviation criterion selects positions whose reused value vector disagrees most with the full-prefill value vector at the detection layer. Its per-token score is simply the value deviation of Equation 1 evaluated at $L_{\text{det}}$, and a position is selected when this score exceeds a multiple of the mean deviation over the reused positions:

(5) $$\mathcal{I}_{\text{dev}} = \left\{\, j\in\mathcal{I}_{\text{reuse}} \;\middle|\; s_{\text{dev}}(j) \geq \tau_{\text{dev}}\cdot\mu_{\text{dev}} \,\right\}, \qquad s_{\text{dev}}(j) = d_{j,\,L_{\text{det}}}$$

The factor $\tau_{\text{dev}}$ is a sensitivity knob: raising it recomputes fewer tokens and reuses more, lowering it does the opposite. Note carefully what the reference is here. The score measures distance to the full-prefill KV — the very quantity the method is trying to avoid computing in full. It is available at selection time only because it is read at the single detection layer, not across the whole model, and the persistence property of Section 3.3 makes that one-layer reading a faithful proxy.

6.2 Influence-based selection — protect what the generation leans on

A token can carry only a small value deviation yet still be worth recomputing if downstream generation attends to it heavily, because even a small error on a heavily-attended token propagates. The influence criterion captures this. During the upstream agent's decoding, RelayCaching accumulates, for each reused position $j$, the total attention weight it received across every decoding step $t$, every layer $\ell$, and every head $h$:

(6) $$s_{\text{inf}}(j) = \sum_{t,\,\ell,\,h} \alpha_{t,\ell,h,j}$$

Positions whose accumulated influence exceeds a multiple of the mean are selected:

(7) $$\mathcal{I}_{\text{inf-score}} = \left\{\, j\in\mathcal{I}_{\text{reuse}} \;\middle|\; s_{\text{inf}}(j) \geq \tau_{\text{inf}}\cdot\mu_{\text{inf}} \,\right\}$$

Attention-derived importance is biased toward early positions, yet the suffix tokens immediately before the reuse boundary tend to exert outsized influence on the newly appended content through attention locality. To correct this bias the method adds the last $K_{\text{suf}}$ trailing tokens as a suffix set, and the influence selection is the union of the score-based set and the suffix set:

(8) $$\mathcal{I}_{\text{inf}} = \mathcal{I}_{\text{inf-score}} \cup \mathcal{I}_{\text{inf-suffix}}$$
Read this carefully — it is the crux for our differentiation. The influence score of Equation 6 is the attention the upstream agent's own decoding paid to position $j$. It is a source-side, task-agnostic quantity: it measures how much this token mattered to the generation that already happened, not how relevant it is to the downstream receiver's next decision. And its role is protective — a high-influence token is recomputed to keep it faithful, never down-weighted or removed. RelayCaching therefore has a genuine per-token importance score, but it is pointed at fidelity, not at relevance to the receiver.

6.3 The final rectification set

The set of tokens actually recomputed is the union of the two criteria — the unfaithful tokens and the influential tokens:

(9) $$\mathcal{I}_{\text{final}} = \mathcal{I}_{\text{dev}} \cup \mathcal{I}_{\text{inf}}$$

Every position in $\mathcal{I}_{\text{final}}$ has its KV recomputed within $[L_{\text{start}}, L_{\text{end}}]$ starting from the hidden states saved at $L_{\text{start}}$; every position outside the set reuses the upstream decoding KV verbatim after RoPE re-alignment. The union — rather than an intersection or a weighted combination — is deliberate: a token is worth fixing if it is either badly wrong or heavily used, and missing either kind is what degrades accuracy. Because both selected subsets are sparse and the recomputation is confined to the middle band, the aggregate reuse rate remains above 80% even though two criteria contribute to the set.

7.4 Ablation and sensitivity

The ablation (Table 3, GSM8K, Llama-3.1-8B-Instruct) removes each component in turn and confirms that both selection criteria are load-bearing: dropping the deviation criterion or the influence criterion each lowers accuracy relative to the full method, and the suffix correction contributes a smaller but consistent gain. The sensitivity study (Figure 7) sweeps the two selection factors and the suffix length, showing the expected trade-off — a larger deviation or influence factor recomputes fewer tokens and raises the reuse rate at a gradual accuracy cost, so the defaults sit where accuracy is still at the full-prefill level while reuse remains above 80%.

Scope caveat. The efficiency numbers are reported on small models (Qwen3-0.6B for the TTFT breakdown) and short prefixes; the accuracy tables use 7–8B models. The appendix reports that the U-shaped layer profile and sparse token deviation recur across six model families, which supports the generality of the observations, but the headline 4.7× and 9.2× figures are specific to the measured configurations and should be read as such.

8. Limitations and When Reuse Breaks

RelayCaching's guarantees are inherited entirely from the three empirical observations, so the method's failure modes are exactly the settings where those observations weaken. Naming them precisely is useful both for reading the paper's scope honestly and for locating where a different design would be needed.

The premise it depends on

  • Reuse only helps when the shared content is a large fraction of the downstream prompt; a receiver that reads only a short quote from upstream has little to relay.
  • The layer band and detection layer are profiled per model on calibration data; a model or task whose deviation profile is not U-shaped would need re-profiling and might not confine cleanly to a middle band.
  • Token deviation must stay sparse. A hand-off that perturbs many positions — a large prefix shift, or an agent that rewrites rather than appends — erodes the sparsity that keeps the reuse rate high.

What the evaluation does not yet show

  • The headline TTFT numbers come from a 0.6B model with a 512-token prefix; the interaction between selective rectification and production-scale batching or paged-attention kernels is not measured.
  • Accuracy is reported on short-form reasoning, knowledge, and code benchmarks; long-horizon agent programs where small per-hop errors could accumulate over dozens of rounds are not stress-tested.
  • The extra decode-time memory for pre-RoPE KV, the $L_{\text{start}}$ checkpoint, and the influence tallies is described qualitatively as small but is not quantified against the KV footprint it saves.

None of these undermines the paper's central claim, which is narrow and well supported: within the profiled regime, the decoding cache is a reusable draft and sparse rectification restores fidelity cheaply. They do mark the boundary of that regime, and it is precisely at that boundary — faithful-but-irrelevant content, accumulating multi-hop error, the receiver's task diverging from the source's — that a receiver-centric, subtractive treatment becomes the natural next question.

9. Relation to Decontaminated KV Selection

Our own line of work frames cross-agent KV reuse as a subtractive, per-token, receiver-decision-relevance decontamination problem: when one agent's cache is reused by another, part of what it carries is irrelevant or even misleading to the receiver's next decision, and the right operation is to remove or down-weight that part — to decontaminate — rather than to faithfully reproduce it. KVCOMM, by contrast, is additive re-alignment: it repairs the reused cache toward a corrected reference. RelayCaching is the closest citer to our work on the selection axis, because it, uniquely among the reuse methods, scores each reused token by importance. This section positions it precisely against our thesis, using the full paper rather than the abstract.

9.1 The three diagnostic questions, answered from the full text

We ask of every cross-agent KV reuse paper the same three questions, because they separate a fidelity method from a decontamination method.

Diagnostic question RelayCaching's answer (from full text)
(a) Does it do per-token importance selection? Yes. Genuinely so — Equations 5–9 score each reused position by value-cosine deviation (Eq. 5) unioned with accumulated decode attention plus a trailing suffix (Eqs. 6–8). This is a real per-token importance score, and it is what makes RelayCaching the closest citer to our selection idea.
(b) Is the action subtractive (decontamination) or additive (repair/avoidance)? Purely additive. Selected tokens are recomputed to restore fidelity to the full-prefill reference; the paper calls this rectification. No token is ever dropped, masked, or down-weighted — every position is either reused verbatim or recomputed. There is no subtraction and no decontamination anywhere in the method.
(c) Does it name the contamination phenomenon? No. The framing is the opposite: decoding KV caches remain highly aligned with full-prefill counterparts, deviations are sparse and localized. The reused cache is treated as a high-fidelity draft carrying an occasional numeric error — never as carrying receiver-irrelevant or harmful information. The word contamination, and any notion of the cache misleading the receiver, is absent.

9.2 The one-line differentiator

RelayCaching scores each reused token by its infidelity to the full-prefill reference and by the attention the source agent's own decoding paid to it, then recomputes the selected tokens to make the cache more faithful; our approach scores each reused token by its relevance — or harm — to the receiver agent's next decision, then subtracts the contaminating tokens to make the cache safer to consume. Same object (per-token scoring of reused cross-agent KV); opposite target (source-side fidelity vs receiver-side decision relevance) and opposite action (additive recompute vs subtractive decontamination).

9.3 A worked example — where the two targets diverge

The cleanest way to see that fidelity and receiver-relevance are different targets is a case where they disagree. Suppose the upstream Developer agent's output contains a long block of boilerplate imports that it attended to heavily while generating (so its accumulated influence is high) and that a full prefill would reproduce almost exactly (so its value deviation is low). RelayCaching's verdict on this block is unambiguous: high influence triggers recomputation under Equation 7, and because deviation is low the recompute simply confirms the reused values — effort spent to keep a faithful copy faithful. Now suppose the downstream Reviewer's task is to judge algorithmic correctness, for which the import boilerplate is irrelevant and its strong KV presence only dilutes the attention the Reviewer can place on the logic. A fidelity method has no way to express this: the block is faithful, so by its objective it is already correct and must be preserved. A decontamination method reaches the opposite verdict — the block is faithful yet irrelevant to the receiver's decision, so it should be down-weighted or removed, not recomputed. Same token, same two signals, opposite action, because the objective is receiver-decision relevance rather than reproduction fidelity.

9.4 Honest verdict on the novelty gap

The full text is more than the abstract suggested, and the honest reading is that RelayCaching narrows — but does not close — our decontamination gap, while it does close a loosely worded version of our novelty claim. The distinction matters and is worth stating plainly.

What is no longer defensible

The bare phrase "per-token importance scoring of reused cross-agent KV" can no longer be claimed as ours alone. RelayCaching has exactly that: a value-deviation criterion unioned with an accumulated-attention influence criterion, evaluated position by position. If our novelty is stated only at that altitude, this paper is prior art that pre-empts it. Any claim we make must drop the generic per-token-scoring framing.

What remains genuinely open

Three axes are untouched by RelayCaching: (i) the action is subtractive — removing or down-weighting KV — not additive recompute; (ii) the scoring target is the receiver's decision relevance, not fidelity to a full-prefill reference; (iii) the phenomenon is named and modeled as contamination, i.e. reused KV that is faithful yet still harmful to consume. RelayCaching addresses none of these; on all three it is on the opposite side.

The genuine threat to flag. A reviewer who reads quickly can see RelayCaching's value-deviation-plus-accumulated-attention selector and conclude that our per-token score is the same idea. The two are structurally similar signals; the difference is not in the existence of a score but in what the score points at and what is done with the selected tokens. Our defense must therefore never rest on having a per-token score — it must rest on the action (subtract, not recompute) and the target (receiver-decision relevance, not source-side fidelity), and on naming and demonstrating a contamination effect that a fidelity-restoring method like RelayCaching cannot even express, because in its worldview a faithful cache is by definition a good one.

10. Related Work in Context

RelayCaching organizes prior KV reuse into three families and defines itself against each. The compact map below situates it, and clarifies why the multi-agent, runtime-generated setting is the axis along which it claims novelty.

Prefix caching

vLLM and SGLang reuse exact-match KV at the prefix. Correct and cheap when the prefix repeats, but the shared content in agent chains sits at non-prefix positions, so the positional-alignment requirement rules it out.

Pre-computed caching

CacheBlend, EPIC, and DroidSpeak encode reusable chunks offline for position-independent stitching. Effective for static RAG documents; inapplicable to agent outputs, which exist only at run time. CacheBlend's value-norm detection also misses the value-cosine deviation axis.

Collaborative-inference reuse

APE aligns independently encoded caches via adaptive scaling; KVCOMM is the first to target cascading multi-agent redundancy via retrieval-based anchor pools. RelayCaching removes the external reference entirely, reusing the immediately upstream decoding cache and rectifying it in place.

Read as a whole, the related work confirms that the prior art on cross-context KV reuse is uniformly additive: it either matches, stitches, aligns, or rectifies caches toward a correct reference. None of these methods asks whether a faithful reused cache might still carry information that the receiving agent should not consume — the question our decontamination line is built on.
