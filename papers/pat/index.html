PAT: Accelerating LLM Decoding via Prefix-Aware Attention with Resource Efficient Multi-Tile Kernel

A vLLM plugin that turns shared-prefix decode attention into pack-forward-merge execution.

Jinjun Yi, Zhixin Zhao, Yitao Hu, Ke Yan, Weiwei Sun, Hao Wang, Laiping Zhao, Yuhao Zhang, Wenxin Li, Keqiu Li · Tianjin University / Stevens Institute of Technology

arXiv:2511.22333Decode attentionPrefix cacheA100/H100Open source

1. Problem

Agentic, tool-use, and RAG workloads often share long hierarchical prefixes. Existing decode attention kernels leave this structure underused: one-query-per-CTA execution reloads the same prefix KV repeatedly, while fixed tiling wastes on-chip resources when prefix and suffix lengths are uneven.

Figure 3/4 region from the paper: attention GEMV and tiling pipeline motivating resource-efficient multi-tile execution.

2. Method

PAT introduces a pack-forward-merge pipeline. Queries are grouped by shared prefix, each group is assigned a tile configuration chosen for GPU occupancy and memory traffic, work is forwarded through multiple streams and split for long KV regions, and the partial outputs are merged with online softmax.

PackGroup queries sharing prefix KV to avoid repeated global-memory loads.
ForwardUse multi-tile kernels and multi-stream execution to reduce bubbles.
MergeCombine partial attention outputs with online softmax.

The paper evaluates synthetic shared-prefix cases, a toolagent trace, and BurstGPT-derived conversation workloads. It compares against FlashAttention, FlashInfer, FastTree, RelayAttention, RelayAttention++, DeFT, and Cascade Inference.

4. Relation to This Repo

  • The repo already observes that FlashAttention efficiency varies strongly with shape; PAT is a concrete ASPLOS 2026 example where shape-specific tiling changes end-to-end TPOT.
  • Prefix-cache hit rate should become a first-class workload parameter if the predictor covers agent/tool/RAG serving.
  • PAT is decode-only; it complements but does not replace prefill/decode scheduling models such as Sarathi, Niyama, and Bullet.

5. Limitations

PAT depends on meaningful shared-prefix structure and on serving-runtime support for grouping requests by prefix. A deployment with low prefix reuse will see less benefit, and the paper does not provide a general predictor for prefill or request admission.
