Bullet: Boosting GPU Utilization for LLM Serving through Spatial-Temporal GPU Resource Sharing

SM-aware co-scheduling that runs prefill and decode together instead of treating hybrid batching as a single shared queue.

Zejia Lin, Hongxin Xu, Guanyi Chen, Zhiguang Chen, Yutong Lu, Xianwei Zhang · Sun Yat-sen University

arXiv:2504.19516A100/H100/H20SM-scaling rooflineSGLang + PyTorchOpen source

1. Problem

Modern LLM serving systems mix a compute-intensive prefill phase with a memory-bound decode phase. Chunked prefill and hybrid batching reduce the worst interference, but they still force both phases to share one scheduling space, so one phase often protects latency by leaving resources idle while the other phase could have used them.

For the current vLLM latency-prediction repo, this paper is relevant because it treats wave quantization, phase-specific resource use, and phase interference as first-class terms rather than residual noise.

Figure 1 from the paper: conventional batching, chunked prefill, and an idealized phase-overlap schedule.

2. Core Idea

Bullet separates temporal scheduling from spatial GPU resource allocation. The scheduler decides which prefill work may run without violating decode SLOs; the resource manager then assigns a bounded number of SMs to that work so prefill consumes slack instead of stealing the full device.

ModelAn SM-scaling roofline model estimates how prefill and decode latency change as SM allocation changes.
ScheduleSLO-aware logic decides when extra prefill can be admitted.
PartitionSM masking via libsmctrl enforces spatial sharing.
ExecuteConcurrent streams run prefill and decode with bounded interference.

The evaluation spans ShareGPT, Azure-Code, and arXiv-Summary workloads, dense Llama3.1 models, and Qwen3-235B-A22B-FP8 MoE. Hardware coverage includes A100-80GB, H100, and H20, so the evidence is not limited to a single accelerator class.

4. Relation to This Repo

  • Add an explicit phase-interference term if the predictor is extended from isolated vLLM steps to online serving.
  • Wave quantization and attention bottlenecks are not small implementation details; Bullet uses them to drive scheduling decisions.
  • The current closed-form model should state that it predicts a full-GPU step unless SM partitioning or MPS-style sharing is enabled.

5. Limitations

Bullet depends on runtime control over SM allocation and on a calibration path for the SM-scaling model. It is a scheduling system with an embedded model, not a fully hardware-portable closed-form latency predictor.
